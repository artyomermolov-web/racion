# Рацион

Автоматический планировщик питания: генерация рационов под целевые КБЖУ с учётом предпочтений, ограничений и бюджета. Веб/PWA, российский рынок, mobile-first, интерфейс на русском.

## Запуск (разработка) — одной командой

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Приложение поднимется на SQLite (`prisma/dev.db`), миграции применяются автоматически. Откройте http://localhost:3000 — вас встретит экран входа; зарегистрируйтесь по почте и паролю, заполните профиль — и на главной появится рацион под вашу норму КБЖУ.

### Наполнение базы продуктов и рецептов

База наполняется отдельной командой (идемпотентно, можно запускать повторно):

```bash
npm run seed
```

В каталоге ~211 продуктов российского рынка (13 групп) и 63 собственных рецепта. Значения КБЖУ — справочные, из `docs/kbju-master.md` и `.scratch/racion-mvp/research/products-ru.md`.

### Проверка с телефона (тот же Wi-Fi)

Dev-сервер слушает `0.0.0.0`. Узнайте IP компьютера (`ipconfig` в Windows → «IPv4-адрес») и откройте на телефоне `http://<IP>:3000`. При необходимости разрешите Node.js в брандмауэре Windows.

Приложение — **PWA**: его можно установить на домашний экран (в мобильном браузере «Добавить на экран „Домой“»). После установки последние отрисованные планы доступны **офлайн** — service worker кэширует оболочку и последние страницы-планы; запросы к API идут только по сети.

## Деплой на VPS (docker-compose + PostgreSQL)

Продакшн-задел: приложение + PostgreSQL одной командой, без ручных правок.

1. **Получите код на сервере.** Репозиторий: `https://github.com/artyomermolov-web/racion`.

   ```bash
   git clone https://github.com/artyomermolov-web/racion.git
   cd racion
   # обновление уже развёрнутого сервера: git pull
   ```
2. Поднимите стек:

   ```bash
   docker compose up -d --build
   ```

Провайдер БД переключать вручную **не нужно**: в git схема остаётся на SQLite (для dev), а на PostgreSQL образ переходит сам при сборке (`sed` в `Dockerfile`). `docker-compose.yml` поднимает Postgres и приложение; контейнер на старте разворачивает схему в базе (`prisma db push`), наполняет каталог (`npm run seed`) и запускает сервер на порту `3000`. Данные Postgres хранятся в томе `racion-db`.

> Почему `db push`, а не `migrate deploy` (как в решении 10). Существующие миграции в `prisma/migrations` — в диалекте SQLite и не воспроизводятся на PostgreSQL. `prisma db push` разворачивает провайдер-независимую схему напрямую, без диалект-зависимых миграций — этого достаточно для задела. Для полноценного продакшна миграции стоит перегенерировать под Postgres (`prisma migrate dev`) и вернуться к `migrate deploy`.

**HTTPS.** Приложение слушает HTTP на `3000` — поставьте перед ним обратный прокси с авто-TLS (Caddy) или nginx + certbot, проксируя `443 → app:3000`.

**Переменные окружения.** `DATABASE_URL` для контейнера задан в `docker-compose.yml` (подключение к сервису `db`). Для локальной разработки достаточно значения по умолчанию из `.env.example` (`file:./dev.db`).

## Стек

Next.js (App Router) + TypeScript + Tailwind, Prisma + SQLite (совместимо с PostgreSQL: смена `provider` и `DATABASE_URL`). Аутентификация — почта + пароль (bcrypt), серверные сессии в httpOnly-cookie. Дизайн-система — нативный iOS-стиль (Apple HIG). PWA: манифест, иконки, service worker (офлайн-оболочка + последние планы).

Полный контекст и решения — в `.scratch/racion-mvp/` (карта, спецификация, тикеты), `CONTEXT.md` (глоссарий) и `docs/kbju-master.md` (расчёты КБЖУ).
