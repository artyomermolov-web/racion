# 09: Ручной лог — добавить / править / удалить запись

**What to build:** Пользователь добавляет съеденное в дневник вручную: жмёт «+ добавить» в приёме, ищет еду (сегмент **Поиск**), задаёт количество (граммы + чипсы-пресеты / штуки при наличии грамм-эквивалента / сервинги для рецепта) с живым превью КБЖУ, добавляет — запись появляется в секции приёма, подытоги и остаток пересчитываются. Запись можно тапнуть и поправить количество, свайпом удалить. Правка продукта в базе не меняет прошлые записи (снапшот).

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] `/core/diary/amount.ts`: `nutrientsForAmount(food, amount)` — продукт `per100×grams/100`; штуки `1 шт × gramsPerPiece → граммы`; рецепт `perServing × servings`; пресеты (½/1/1½ порции, «1 шт», «100 г») над теми же полями; округление по `kbju-master.md` A1.
- [ ] Юнит-тест `core/diary/amount.test.ts` (граммы↔сервинги↔штуки, пресеты; штуки без `gramsPerPiece` недоступны) + тест неизменяемости снапшота (изменение исходных данных еды не меняет ранее посчитанный снапшот).
- [ ] `src/lib/diary.ts`: запись/правка/удаление `DiaryEntry` со снапшотом КБЖУ на момент записи; правка количества пересчитывает снапшот из текущих данных.
- [ ] Server actions `addEntry`/`updateEntry`/`deleteEntry` (через `requireUser()` → `src/lib/diary.ts`).
- [ ] Шит добавления, сегмент **Поиск** (базовые `Ingredient`+`Recipe` и своя кастом-еда через `src/lib/food.ts`); экран количества с живым превью КБЖУ; штучный ввод скрыт для продукта без `gramsPerPiece`.
- [ ] Приём (слот) предзаполнен (следующий незаполненный приём дня, иначе `snack`), можно сменить.
- [ ] Записи рендерятся в секциях приёмов как «название · количество · ккал» + подытог приёма; тап — правка, свайп — удалить; остаток/сводка (тикет 08) обновляются.
