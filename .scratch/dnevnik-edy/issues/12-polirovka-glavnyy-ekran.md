# 12: Полировка и опциональная строка на главном экране

**What to build:** Доведение всех состояний дневника до аккуратного вида и опциональная точка входа с главного экрана. Пользователь во всех крайних случаях видит понятный экран (нет нормы / пустой день / пустая база блюд / штуки без грамм-эквивалента), а на главном — опциональную строку «залогировано X / цель Y» с «не хватает белка — что поесть?», ведущую в дневник к блоку подсказок.

**Blocked by:** 08, 09, 10

**Status:** ready-for-human

- [x] Финальные тексты и вид пустых/ошибочных состояний: нет активного профиля → «заполни профиль» (уже в `DayBody`/`HomeContent`, тикеты 08/06); пустой день → сводка остатка + доступный блок «что поесть» (тикеты 08/10); пустая база кандидатов → **честное сообщение, отделённое** от «нет под фильтр усилий» (новый флаг `baseEmpty`); штуки без `gramsPerPiece` → только граммы (уже в `LogSheet`/ядре `amount.ts`, тикеты 09/38).
- [x] Опциональная строка на главном экране: «залогировано X / цель Y» + «не хватает белка — что поесть?» со ссылкой в дневник (US 39) — новый `home/DiaryHomeRow`.
- [x] Согласованность со стилем «Трекер / Apple HIG» (кольца/бары/чипсы/секции), проверка light+dark.

**Границы (сознательно НЕ здесь):** офлайн/PWA записей дневника — вне под-проекта; недельная рябь и список покупок — вне охвата дня.

## Comments

- Реализовано. Изменения только в тонких слоях (lib/UI/CSS) — ядро `/core/diary` и `/core/generator` не тронуты; все 353 теста, typecheck и `npm run build` зелёные.
- **Различение пустых состояний блока «Что поесть сейчас».** `getSuggestions` теперь возвращает `baseEmpty`: пусто под текущим фильтром — делаем контрольный прогон `suggestNextMeal` без фильтра усилий (`limit: 1`); если и там пусто → база рецептов пуста или всё под жёсткими ограничениями (честный текст «наполните базу / ослабьте ограничения»), иначе → «нет под этот фильтр усилий, смените чипсы». Тонкий слой `src/lib/diary.ts` намеренно без своего шва (spec, Testing Decisions) — логика скоринга/остатка уже покрыта `core/diary/*`.
- **Опциональная строка на главном (US 39).** Клиентский `DiaryHomeRow` тянет день тем же `getDayLogAction` под **локальную** дату (как экран дня — без UTC-дрейфа границы «сегодня»), показывает «залогировано X / цель Y ккал» + бар + CTA-ссылку в `/dnevnik`. Отстающий макрос → «Не хватает белка/жиров/углеводов — что поесть?»; иначе остаток ккал; иначе «план закрыт». Без активной нормы (`progress === null`) строка не рендерится — главный экран показывает своё «заполни профиль». Размещена вверху `HomeContent` (над сегмент-контролом) — видна и на «Сегодня», и на «Неделя».
- Проверено в браузере (light + dark): строка на главном, переход в дневник по клику, приоритет белка в блоке подсказок, честные пометки вариантов. Стиль согласован с трекером (карточка-группа, бар как у макро-баров, токены темы).
- Оставшийся тестовый лог «Творог с ягодами» за 2026-09-11 (из верификации тикета 10) — данные локальной dev-БД, кода не касается.
