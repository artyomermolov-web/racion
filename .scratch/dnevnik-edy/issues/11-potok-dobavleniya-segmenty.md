# 11: Поток добавления — сегменты Недавнее / Избранное / Своё

**What to build:** Шит добавления (из тикета 09) обрастает остальными сегментами, чтобы дотянуться до нужной еды быстрее поиска: **Недавнее** (что уже логировал), **Избранное** (избранные рецепты + часто добавляемые продукты), **Своё** (кастом-продукты и кастом-рецепты). Из любого сегмента еда логируется тем же экраном количества, что и из Поиска.

**Blocked by:** 09

**Status:** ready-for-human

Опирается на факты тикета [01](01-dannye-shtuki-istochniki.md): источники сегментов. Решение развилки: отдельной модели избранного продукта нет — «частые продукты» выводятся из `DiaryEntry`.

- [x] `src/lib/diary.ts`: запросы сегментов — *Недавнее* и частые продукты (агрегат по `DiaryEntry` пользователя), *Избранное* (`FavoriteRecipe` рецепты + частые продукты из лога), *Своё* (`isCustom`+`ownerUserId` на `Ingredient`/`Recipe`).
- [x] Шит: сегмент-контрол Поиск · Недавнее · Избранное · Своё; выбор из любого сегмента ведёт на тот же экран количества (тикет 09).
- [x] Пустые состояния сегментов (нет истории → Недавнее пусто; нет избранного → подсказка).

**Резолюция:** чистое ядро `core/diary/segments.ts` (`recentRefs`/`frequentIngredientRefs`/`favoriteRefs` над ссылками `source+refId`) + 12 юнит-тестов (дедуп по свежести, частота с tie-break по свежести, рецепты вне «частых продуктов», порядок избранного). Слой `src/lib/diary.ts#getLogSegments`: 4 индексных чтения (`DiaryEntry`-агрегат, `FavoriteRecipe`, кастом `Ingredient`/`Recipe`) → упорядочивание делегируется ядру; возвращает ссылки, а имя/КБЖУ/пометку «Своё» UI берёт из уже загруженной базы (без дубля снапшота). Новых сущностей/таблиц нет. Тонкий `getLogSegmentsAction()` через `requireUser()`. UI: `LogSheet` получил сегмент-контрол Поиск · Недавнее · Избранное · Своё (состояние сегмента и данных живёт в шите, переживает «‹ Назад»); Поиск — по загруженной базе, остальные сегменты резолвят ссылки в строки базы (удалённая еда отсеивается), общий `FoodRow`; пустые состояния 🕘/⭐️/✏️. Выбор из любого сегмента ведёт на тот же экран количества (тикет 09). typecheck + 353 теста зелёные; сквозной прогон в браузере (все 4 сегмента, выбор → количество → добавить, пустое «Своё») подтверждён. Двухосевое ревью (Standards + Spec): жёстких нарушений нет; по замечанию Standards вынесен резолвер `resolveSegmentRef` (снят дубль сборки строки).

**Границы (сознательно НЕ здесь):** новых сущностей не заводим; порядок/дефолтный сегмент — по UX-решению внутри тикета.
