## Question

Зафиксировать UX-поток ручного добавления записи (шит), выезжающий по «+ добавить» / из пустого приёма. Обвязка вокруг килфичи — но отдельная поверхность от экрана дня (тикет 04).

**1. Сегменты выбора еды.** `Поиск · Недавнее · Избранное · Своё` (источники — факты из тикета 01):
- *Поиск* — по базовым `Ingredient` + `Recipe` (+ своё попадает сюда же).
- *Недавнее* — из прошлых `DiaryEntry` (иного источника истории в схеме нет — факт из тикета 01; сегмент пуст до первых записей).
- *Избранное* — сегодня есть только `FavoriteRecipe { userId, recipeId }` = **рецепты**; избранного/частоты для **продуктов** нет ни модели, ни счётчика (факт из тикета 01).
- *Своё* — кастом-еда (`isCustom`+`ownerUserId` на `Ingredient`/`Recipe`); в поиск попадает через `OR[ownerUserId null|=userId]` в `src/lib/food.ts`, помечается `own` — готово как есть.
Определить порядок сегментов и дефолтный.

**⚠ Развилка (graduated из тикета 01) — «Избранное» для продуктов.** Решить в этом тикете:
- (A) MVP: «Избранное» = только рецепты (`FavoriteRecipe`), а «частые продукты» — агрегат по `DiaryEntry` (топ по частоте за период); отдельной модели избранного продукта не заводим.
- (B) Завести модель избранного продукта (напр. `FavoriteIngredient`) — тогда это **правка тикета 02** (модель данных), а не только UX.
Рекомендация — (A): не тянуть новую таблицу, «часто ем» естественно выводится из лога. Если выбрано (B) — вернуть развилку в тикет 02.

**2. Экран количества.** После выбора еды — ввод количества: **граммы+чипсы (½/1/1½, «100 г») / штуки (если есть `gramsPerPiece`) / сервинги (для рецепта)** с **живым превью КБЖУ**. Если у продукта нет `gramsPerPiece` — «шт» скрыта, доступны только граммы (крайний случай из дизайна).

**3. Приём и добавление.** Приём (slot) **предзаполнен** (следующий незаполненный / текущий по времени — определить правило), пользователь может сменить; кнопка «Добавить» создаёт `DiaryEntry` со снапшотом КБЖУ.

**4. Крайние случаи.** Штуки без грамм-эквивалента (см. выше); правка существующей записи открывает тот же экран количества с пересчётом снапшота.

**Тесты (закладываем в спеку):** `amount.ts` — граммы↔сервинги↔штуки (пересекается с тикетом 02, здесь — с точки зрения UX-пресетов и превью).
