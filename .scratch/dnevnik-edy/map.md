## Destination

**Build-ready спека `spec.md` под-проекта A** — дневник еды (лог съеденного) + движок-килфича «что поесть сейчас», который на остатке КБЖУ дня выдаёт 2–3 конкретных варианта с приоритетом на отстающий макрос и логом «съел» в один тап. Карта фиксирует все решения (тикеты-вопросы ниже) и заканчивается синтезом `spec.md`, готовой к передаче в `writing-plans`. **Планирование, не стройка:** карта производит решения, кода не пишет; исполнение — отдельная сессия после спеки.

Опора — исходный дизайн: [20260907fooddiarydesign.md](./20260907fooddiarydesign.md) (копия промта). Строится поверх готового `racion-mvp` (одна кодовая база, один аккаунт, один движок КБЖУ).

**✅ Destination достигнут:** [spec.md](./spec.md) (`ready-for-agent`) — синтезирована навыком `to-spec`. Тикеты-решения 02–07 свёрнуты в спеку напрямую (короткое замыкание HITL-прогона по решению пользователя); карта остаётся историей решений, спека — источником для стройки.

## Notes

**Домен:** глоссарий — `CONTEXT.md` в корне (термины `слот`, `порция`, `норма`, `профиль питания`, `кладовка`, `избранное`, `recurring`, `keyword-фильтр` уже определены). Новые термины дневника (`запись дневника`, `остаток/дельта`, `подсказка`, `грамм-эквивалент штуки`) фиксировать в `CONTEXT.md` по мере кристаллизации. При изменении модели — навыки `grilling` + `domain-modeling`.

**Фундамент расчётов:** `docs/kbju-master.md` первичен для любых числовых значений (энергия/макросы/клетчатка). Клетчатка — только нижняя граница.

**Опора на существующий код (не пере-решаем):**
- `Ingredient` хранит КБЖУ на 100 г/мл, `unit=g|ml|pcs`, кастом через `isCustom`+`ownerUserId`.
- `Recipe.servings`; КБЖУ считается из состава (`core/nutrition/recipe.ts`), не хранится.
- Цель дня — середины активного `NutritionProfile` → `DayTarget` (тип в `core/generator/types.ts`). В MVP ровно один активный профиль.
- Ядро генератора (`core/generator/*`) **переиспользуем как есть, не меняем** — движок подсказок строится поверх (`GeneratorRecipe`, `bestPortion`, скоринг, `GeneratorConstraints`, `Preferences`).
- Планы не персистятся — генерируются на лету; дизайн это учитывает.
- Архитектура — **вариант A**: новый чистый модуль `/core/diary` (без Prisma/Next, тот же шов тестов Vitest); план/подсказка и факт-запись — разные сущности, связь тонким адаптером.

**Стиль:** дневник наследует визуальную систему «Трекер / Apple HIG» из `racion-mvp` (`prototype/screens.html`) — стиль заново не выбираем; прототип тикета 04 расширяет её (блок «что поесть» + чипсы усилий). Интерфейс на русском, метрические единицы, локальная дата пользователя.

**По типам тикетов вызывать навыки:** `research` → Skill "research"; `prototype` → Skill "prototype"; `grilling` → Skill "grilling" + "domain-modeling"; `task` → выполнить работу и записать факты.
