`wayfinder:map`

## Destination

**Build-ready спека `spec.md`** дневник-центричного редизайна: вкладка **Дневник** становится первой и стартовой; операции вкладки **«Меню»** (`/home`) — заменить блюдо, удалить приём, перегенерировать, «Неделя» — переезжают в Дневник; рецепт **раскрывается инлайн по тапу**; действия («съел», «заменить», «удалить», «добавить») — **иконки в стиле Apple HIG** без текстовых подписей; добавление еды — **визуальное «как в Yazio»** (плитки/карточки с эмодзи-иконкой по группе продукта). Карта фиксирует решения (тикеты ниже) и заканчивается синтезом `spec.md`, готовой к передаче в `writing-plans`.

**Планирование, не стройка:** карта производит решения и прототипы, боевого кода не пишет. Стройка — отдельная сессия после спеки.

**✅ Destination достигнут:** [spec.md](./spec.md) (`ready-for-agent`) — синтезирована навыком `to-spec`. Тикеты-решения/прототипы 01–06 свёрнуты в спеку напрямую (short-circuit HITL-прогонов по решению пользователя); карта остаётся историей решений, спека — источником для стройки. Решения синтеза (особенно слияние двух «съел») помечены в спеке **[синтез]** и подлежат сверке перед версткой.

**🏗 Стройка нарезана (`to-tickets`):** вертикальные срезы-«трассирующие пули» — тикеты **08–13** (`ready-for-agent`): [08 сборка ленты (ядро+тесты)](issues/08-sborka-lenty-dnya-core.md) → [09 единая лента + слияние «съел»](issues/09-edinaya-lenta-sliyanie-sel.md) → [10 навигация](issues/10-navigatsiya-dnevnik-glavnyy.md) → {[11 иконки + раскрытие рецепта](issues/11-ikonki-i-raskrytie-recepta.md)} → {[12 визуальный пикер](issues/12-vizualnyy-piker-emodzi.md) (←11), [13 экран недели](issues/13-ekran-nedeli.md) (←10,11)}. ## Notes

**Домен:** глоссарий — `CONTEXT.md` в корне. Ключевой термин, который родится в тикете [01](issues/01-model-edinoy-lenty-dnya.md), — **«единая лента дня»** и состояния приёма (предложено / запланировано / съедено-из-плана / съедено-вручную / добавлено-сверху). Записать в `CONTEXT.md` после резолва 01. При изменении модели — навыки `grilling` + `domain-modeling`.

**Опора на существующий код (не пере-решаем):**
- Две разные сущности: **план** (`/home`, генерится на лету, не персистится; отметка «съел» списывает кладовку — `markEatenAction`) и **запись дневника** (`DiaryEntry`, персистится, `/dnevnik`). Слияние их «съел» — центральная развилка (тикет 01).
- `WeekPlan` (`src/components/WeekPlan.tsx`), `DayPlan` (`src/components/DayPlan.tsx`), `DiaryScreen` (`src/app/(app)/dnevnik/`) — источники операций, которые переезжают/сливаются.
- **Картинок еды в проекте нет** (факт проверен): ни поля в схеме Prisma, ни в типах, ни в сиде, ни ассетов, ни маппинга группа→эмодзи. Есть только 4 PWA-иконки в `public/`. Поэтому визуальный ряд строим на **эмодзи/SVG по группе продукта**, реальные фото — Out of scope.
- HIG-иконки = SF Symbols (недоступны в вебе) → реализуем **своим набором инлайн-SVG** в стиле HIG (как уже сделан `TabBar.tsx`), без зависимостей.

**Стиль:** наследуем визуальную систему «Трекер / Apple HIG» из `racion-mvp` (`prototype/screens.html`) и `dnevnik-edy`. Русский интерфейс, метрические единицы, локальная дата.

**По типам тикетов вызывать навыки:** `research` → Skill "research"; `prototype` → Skill "prototype"; `grilling` → Skill "grilling" + "domain-modeling"; `task` → выполнить работу и записать факты.
