# 09: Единая лента в Дневнике со слиянием «съел»

**What to build:** Дневник показывает предложенные приёмы сгенерированного плана и съеденное одной лентой дня (по сборке из 08). Тап «съел» по предложенному приёму одной операцией создаёт запись `DiaryEntry` (двигает остаток КБЖУ дня) и списывает кладовку (`markMealEaten`); снятие отметки обратимо (удаляет запись + возвращает лоты). «Заменить / Удалить / Перегенерировать остаток» работают над предложенными приёмами, не трогая съеденное. Действия пока текстовые (иконки — тикет 11). Вкладку «Меню»/`/home` в этом тикете не трогаем.

**Blocked by:** 08.

**Status:** resolved

Ключ (spec.md, решение 01): два «съел» ортогональны — `DiaryEntry` = питание/остаток, `MealWriteOff` = кладовка; один тап триггерит оба; идемпотентность держат уже существующие уникальные индексы `DiaryEntry(userId,date,slot,suggestedRecipeId)` и `MealWriteOff(userId,mealKey)`. Остаток дня — единый, из `getDayLog`→`progress`.

- [x] Лента дня Дневника рендерит позиции из сборки 08: предложенные приёмы + съеденное, с визуально различимыми статусами и подытогами по слотам.
- [x] Тап «съел» по предложенному приёму создаёт `DiaryEntry` и списывает кладовку в одной операции; остаток дня сдвигается; повтор не задваивает ни запись, ни списание.
- [x] Снятие «съел» удаляет запись и возвращает списанное в лоты.
- [x] «Заменить» подбирает другое блюдо под остаток дня; «Удалить» убирает предложенный приём; «Перегенерировать остаток» даёт свежие предложения, не трогая съеденное (переиспользовать существующие `replaceMealAction` / `regenerateRemainder`).
- [x] Продукт (не рецепт): «съел» создаёт запись без списания кладовки; действия «заменить» у него нет.
- [x] Предупреждение «кладовки не хватило» показывается при нехватке запаса.
- [x] Блок «Что поесть сейчас» и листание дней сохраняются; честные пустые состояния (нет нормы / пустая база) сохраняются.
- [x] Прогон в браузере: съеденное из плана отражается в остатке Дневника (свежая вкладка, пересобрать `.next` при новых маршрутах).

## Comments

Реализовано (single-context агент): сервер — `buildDayForDate` (детерминированный по дате план) + слияние «съел» `eatPlanMeal`/`uneatPlanMeal` в `src/lib/diary.ts` (общий идемпотентный `logFoodOnce` с `logSuggestion`); клиент — новый `DayFeed.tsx` (сборка `assembleDayFeed`, текстовые действия). Браузерный прогон подтвердил оба «съел» одним тапом (DiaryEntry + MealWriteOff по ключу `date|slot|recipe|portion|0`), обратимость (лоты вернулись), замену и перегенерацию остатка с сохранением съеденного.

Известные границы (осознанные, по тикету «переиспользовать существующие экшены»): (1) «Заменить» сайзит остаток только по приёмам плана, ручные extra-записи в baseline не входят — та же граница, что на `/home`; (2) перегенерация остатка пересобирает extra-продукты не точно (ядро восстанавливает только рецепты из пула) — тоже как на `/home`. Обе устранятся при отвязке плана от клиента в будущих тикетах. `/home` и строка `DiaryHomeRow` в этом тикете не трогались (кроме уже лежавшего в рабочем дереве defensive `.catch`).
