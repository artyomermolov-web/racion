# 08: Сборка ленты дня в /core/diary

**What to build:** Чистая функция ядра, сливающая предложенные приёмы сгенерированного плана и залогированные записи дневника (`DiaryEntry`) одного дня в единый упорядоченный таймлайн со статусами приёма и подытогами по слотам. Это основа дневник-центричного редизайна: на ней стоят лента дня (09), навигация (10) и всё остальное. Демо-фичей сама не является — проверяется юнит-тестами.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

Модель (из spec.md, решение тикета 01): позиция ленты несёт `status` — `suggested` (приём плана без соответствующей записи), `eaten` (есть `DiaryEntry`), `extra` (съедено вне плана). `DiaryEntry` — источник правды питания/остатка; `MealWriteOff` — отдельный факт кладовки (в этом тикете не трогаем).

- [ ] В `/core/diary` добавлена чистая функция сборки ленты дня: вход — предложенные приёмы (slot/recipeId/portion/nutrients) + записи `DiaryEntry` дня; выход — упорядоченный список позиций со `status` (`suggested`/`eaten`/`extra`) и подытогами по 4 слотам в каноническом порядке.
- [ ] Съеденный приём не дублируется предложенным (если под предложенный приём есть запись — позиция одна, `eaten`).
- [ ] Продукт без рецепта корректно попадает в ленту (без действий «заменить»).
- [ ] Функция тотальна и детерминирована (без Prisma/Next); экспортирована из `@/core/diary`.
- [ ] Юнит-тесты по внешнему поведению (прайор-арт `aggregate.test.ts`/`progress.test.ts`): пустой день (все `suggested`), частично съеденный (микс), съеденное вне плана (`extra`), продукт без рецепта, идемпотентность статуса при повторе.
- [ ] Новые термины (`лента дня`, `состояние приёма`) внесены в `CONTEXT.md`.
