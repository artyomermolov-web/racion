# Спек: Интеграция ВкусВилл MCP как источника каталога, КБЖУ, цен и функций

**Status:** ready-for-agent

Опорные решения: [ADR-0001](../../docs/adr/0001-vkusvill-edinyy-istochnik-sync.md) (ВВ — единый источник через синк, не live), [ADR-0002](../../docs/adr/0002-geo-tolko-lokator-ceny-nacionalnye.md) (гео = только локатор). Термины — см. `CONTEXT.md`, раздел «Термины — ВкусВилл».

## Problem Statement

Пользователь хочет, чтобы рацион строился на реальных данных ВкусВилл: КБЖУ, стоимость и ассортимент — настоящие, а не захардкоженные и помеченные как ненадёжные. Сейчас каталог (211 ингредиентов) и цены зашиты в seed; цена «ориентир», магазина/города/региона в системе нет вовсе, никаких внешних интеграций нет. Из-за этого смета недостоверна, ассортимент оторван от того, что реально можно купить, и нельзя одним действием собрать корзину в ВкусВилл.

## Solution

Racion подключается к публичному MCP-серверу ВкусВилл (`https://mcp001.vkusvill.ru/mcp`, открытый, без ключа) и делает его источником истины по каталогу, КБЖУ и цене. Данные периодически синхронизируются в локальную базу (CLI-команда), генерация и список покупок работают по свежему снапшоту. Все 8 функций MCP находят место в продукте:

- **Каталог/поиск** (`products_search`) наполняет базу и питает пикер добавления продукта.
- **КБЖУ и цена** товаров парсятся из ответов ВВ; при нескольких поставщиках КБЖУ усредняется.
- **Рецепты ВВ** (`recipes`) импортируются как рецепты Racion (у них чистые структурные КБЖУ и привязка к товарам).
- **Аналоги** (`product_analogs`) стоят за кнопкой «Заменить» на экране Неделя.
- **Штрихкод** (`product_barcode`) добавляет продукт в кладовую/дневник по сканированию.
- **Акции** (`products_discount`) показываются бейджем и фильтром.
- **Магазины** (`shops`) — локатор в профиле (регион/город/метро), справочный.
- **Корзина** (`cart_link_create`) — кнопка «Открыть корзину во ВкусВилл» на списке покупок; ссылка, не заказ.

Существующий seed-каталог ре-сорсится: где ингредиент сопоставляется с товаром ВВ — берутся настоящие КБЖУ/цена и проставляется провенанс; несопоставленное остаётся с фолбэком и в смету по стоимости не попадает (смета помечается как частичная).

## User Stories

1. Как пользователь, я хочу видеть в карточке продукта настоящие КБЖУ из ВкусВилл, чтобы доверять цифрам рациона.
2. Как пользователь, я хочу, чтобы стоимость списка покупок считалась по реальным ценам ВкусВилл, чтобы смета была правдоподобной.
3. Как пользователь, я хочу, чтобы генератор собирал рацион из продуктов, которые реально есть в ассортименте ВкусВилл, чтобы план был исполним.
4. Как пользователь, я хочу видеть, когда цена по позиции неизвестна (нет мэтча с ВВ), чтобы понимать, что итоговая смета приблизительная, а не ошибочная.
5. Как пользователь, я хочу одним действием открыть корзину во ВкусВилл со всеми продуктами недели, чтобы не собирать её вручную.
6. Как пользователь с длинным списком покупок (>20 позиций), я хочу получить несколько ссылок-корзин, чтобы в корзину попало всё, а не только часть.
7. Как пользователь, я хочу заменить блюдо/продукт на аналог из ВкусВилл прямо на экране Неделя, чтобы быстро подобрать замену из реального ассортимента.
8. Как пользователь, я хочу добавить продукт в кладовую или дневник по штрихкоду, чтобы не искать его вручную.
9. Как пользователь, я хочу видеть акционные товары (бейдж «Акция») и фильтровать их, чтобы экономить.
10. Как пользователь, я хочу выбрать свой регион/город/метро в профиле и видеть ближайший магазин ВкусВилл (адрес, часы), чтобы понимать, где забрать заказ.
11. Как пользователь, я хочу, чтобы новые рецепты, попадающие в базу, считались по данным ВкусВилл, чтобы их КБЖУ были достоверны.
12. Как пользователь, я хочу, чтобы импортированные из ВкусВилл рецепты приходили с шагами приготовления и КБЖУ, чтобы ими можно было пользоваться сразу.
13. Как пользователь, я хочу искать продукты в пикере добавления по каталогу ВкусВилл, чтобы добавлять реальные товары.
14. Как пользователь, я не хочу видеть цену по карте лояльности как основную, чтобы не обмануться в смете без карты.
15. Как поддерживающий разработчик, я хочу обновлять каталог/цены одной командой (`npm run vv:sync`), чтобы держать данные свежими без ручной правки seed.
16. Как поддерживающий разработчик, я хочу, чтобы синк был идемпотентным (upsert), чтобы повторный прогон не плодил дубли.
17. Как поддерживающий разработчик, я хочу видеть в базе провенанс каждого ингредиента (`seed`/`vkusvill`) и `vvXmlId`, чтобы отличать настоящие данные от фолбэка.
18. Как поддерживающий разработчик, я хочу, чтобы сетевые вызовы ВВ были в одном тонком адаптере, чтобы вся логика оставалась чистой и тестируемой на фикстурах.
19. Как поддерживающий разработчик, я хочу, чтобы охват синка был курируемым, чтобы не упереться в rate-limit и не взорвать детерминированные тесты.
20. Как поддерживающий разработчик, я хочу переиспользуемый парсер КБЖУ-строк ВВ, чтобы одинаково разбирать формат во всех местах.
21. Как пользователь, я хочу, чтобы при недоступности/лимите ВкусВилл приложение продолжало работать на последнем снапшоте, чтобы фича не падала целиком.

## Implementation Decisions

**Архитектура данных (ADR-0001).**
- ВкусВилл — источник истины; синхронизация в локальную Prisma, генерация по снапшоту. Live-вызовы MCP только для `cart_link_create` и (опционально) точечного освежения цены — не для генерации.
- Сеть изолирована в одном тонком адаптере `src/lib/vkusvill/client.ts` (JSON-RPC 2.0, `tools/call`, обработка `{ok,error}`-конверта, rate-limit/ретраи, UTF-8 тела). Адаптер — единственная точка сети.

**Модель (schema changes).** На `Ingredient` добавляются поля провенанса и ВВ-данных: `source` (`seed | vkusvill`), `vvXmlId` (int/строка, nullable, индекс), `vvPriceOld?`, `vvDiscountPct?`, `vvUpdatedAt?`. Существующие поля КБЖУ/упаковки сохраняют смысл (per-100, `packSize`, `pricePerPack`, `gramsPerPiece`). Для рецептов, импортированных из ВВ, помечается происхождение (напр. `source`/внешний id на `Recipe`).

**Мэппинг товара ВВ → Ingredient (Q10).**
- Штучный товар (`unit:"шт"`, `weight` в кг) → `unit=pcs`, `gramsPerPiece = weight*1000`, `packSize=1`, `pricePerPack = price.current`.
- Весовой/фасовка по массе → `unit=g`, `packSize = weight*1000`, `pricePerPack = price.current`.
- Скидка: смета считается по `price.current`; `price.old`/`discount_percent` кладутся в `vvPriceOld`/`vvDiscountPct` только для бейджа. **Цена по карте лояльности не подставляется** как основная.

**КБЖУ-парсер (Q7).** `parseVkusvillNutrition(raw) → FoodNutrients` (тип из `core/nutrition`): чистит `&nbsp;`/`<br>`/экранирование, разбирает «белки/жиры/углеводы/ккал», при нескольких поставщиках возвращает **среднее** по вариантам. Сырая строка и число вариантов сохраняются для аудита.

**Ре-сорс и мэтчинг (Q5=b, Q9=c).** `matchIngredient(seed, candidates) → match | null` сопоставляет seed-ингредиент с товаром ВВ (по названию/нормализации, при необходимости группе). Сопоставленные — `source=vkusvill` с настоящими КБЖУ/ценой; несопоставленные — `source=seed`, фолбэк-КБЖУ (остаются в меню и в расчёте КБЖУ), но **исключаются из стоимости**; итоговая смета помечается `partial`.

**Импорт рецептов (Q6=a).** `recipeToRecipe(vvRecipe, catalogIndex) → {recipe, matchedRatio}`: ингредиенты рецепта ВВ мэтчатся к каталогу по их `ids`; рецепт импортируется при `matchedRatio ≥ 0.8`, иначе пропускается. Меню-единицей остаётся `Recipe` Racion; КБЖУ берутся из структурного `nutritional` рецепта ВВ / считаются из состава.

**Синк (Q4=a, Q8).** CLI `npm run vv:sync`: курируемый охват (нужные пищевые категории + товары, на которые ссылаются импортируемые рецепты + ограниченный стартовый набор рецептов), идемпотентный upsert (ключ — `vvXmlId`/slug). Cron — позже. Пагинация 10/стр. обходится итерацией по `page`; учитывается rate-limit (`product_analogs` предпочтительнее `product_details` там, где нужны полные карточки).

**Корзина (Q2, Q11).** `buildCartChunks(lines) → {xml_id,q}[][]` бьёт список покупок на группы ≤20 позиций; для каждой группы live-вызов `cart_link_create` даёт `share_basket`-URL. UI: кнопка «Открыть корзину во ВкусВилл» на списке покупок (несколько ссылок при длинном списке). Это ссылка, не заказ/оплата — под ограничения на финансовые действия не попадает.

**Гео (ADR-0002, Q3=b).** Профиль хранит выбор региона/города/метро (id-фильтры `shops`); показывается ближайший магазин (адрес/часы/координаты). На КБЖУ/цену/генерацию не влияет.

**Покрытие функций MCP (Q11-карта).** `products_search`→пикер; `product_analogs`→«Заменить» (Неделя); `product_barcode`→добавление в кладовую/дневник; `products_discount`→бейдж «Акция»+фильтр; `cart_link_create`→корзина; `shops`→локатор; `recipes`→импорт; `product_details`→точечно (по возможности, с учётом 429).

**Устойчивость.** При недоступности/лимите ВВ приложение работает на последнем снапшоте; онлайн-действия (корзина, аналоги, поиск в реальном времени) деградируют мягко с понятным сообщением.

## Testing Decisions

Хороший тест здесь проверяет **внешнее поведение чистой трансформации**, а не детали реализации: на вход — зафиксированный реальный JSON-ответ ВВ (fixture), на выход — ожидаемая строка каталога / смета / набор корзин. Сеть, Prisma, Next в юнит-тесты не входят.

Швы (подтверждены с заказчиком):

- **Шов 1 — новый чистый модуль `src/core/vkusvill/`** (fixtures из реальных ответов ВВ):
  - `parseVkusvillNutrition` — разбор и усреднение по поставщикам (кейсы: один поставщик, несколько через `<br>`, мусорные символы, отсутствующее поле).
  - `productToIngredient` — мэппинг штучного и весового товара, перенос скидки в отдельные поля.
  - `matchIngredient` — совпадение/несовпадение, нормализация названий.
  - `recipeToRecipe` — импорт при ≥80% и пропуск при <80%.
  - `buildCartChunks` — разбиение на группы ≤20, дробные количества.
- **Шов 2 — расширение существующего `src/core/shopping`** (`list.test.ts`): несопоставленные позиции исключаются из стоимости, выставляется флаг `partial`, КБЖУ/меню не страдают.

Прир-арт: `src/core/nutrition/recipe.test.ts`, `catalog.test.ts`, `src/core/shopping/list.test.ts`, `units.test.ts`, `src/core/generator/*.test.ts` — тот же стиль чистых модулей на vitest.

Вне юнит-тестов (край, проверка на реальных данных + `npm run build`): MCP-клиент, CLI-синк, миграции Prisma, server actions, UI (пикер/«Заменить»/список покупок/профиль-локатор/штрихкод).

## Out of Scope

- Оформление и оплата заказа во ВкусВилл (MCP этого не умеет; `cart_link_create` — только ссылка). Финансовые действия — не выполняем.
- Поштучная цена/наличие по конкретному магазину/городу (MCP не отдаёт; см. ADR-0002).
- Автоподстановка цены по карте лояльности как основной.
- Cron/автоматическое расписание синка (сейчас — ручная CLI; позже отдельно).
- Полное зеркалирование всего каталога ВВ (охват курируемый).
- Пересмотр самих формул КБЖУ/нормы (`docs/kbju-master.md` остаётся первичным для расчётов; меняется лишь источник исходных значений КБЖУ/цены).

## Further Notes

- Память проекта: расширение seed сдвигает детерминированные недельные leak-тесты — правится на уровне генератора/вердикта, не подбором данных под seed. Синк каталога это заденет; заложено отдельным пунктом в тикете синка.
- `Ingredient.group` хранит русскую подпись («Яйца»/«Крупы…»), а не ключ — мэппинг категорий ВВ учитывает это.
- Cyrillic в MCP слать реальным UTF-8 (шелл `-d` ломает — использовать тело файлом/`--data-binary`).
- Пагинация всех списков ВВ фиксирована 10/стр.; итерировать по `page`, следить за `meta.has_more`.
