## 1. Eat This Much — полный разбор функциональности

### 1.1 Онбординг и расчёт КБЖУ

- **Регистрация по email**, физпараметры собираются в процессе (можно отредактировать позже — ни один шаг не финальный).
- **Профиль пользователя:** рост, вес, возраст, пол, % жира, уровень активности, единицы (метрика/имперская), **день закупки** (определяет старт недели и время автогенерации).
- **Nutrition Profiles (профили питания):** контейнеры целевых калорий + макросов; дополнительно лимиты по клетчатке, натрию, холестерину. Можно иметь несколько профилей (например «тренировочный день» / «день отдыха»).
- **Калькулятор КБЖУ:** формула Mifflin-St Jeor (BMR) + множитель активности + корректировка под цель (−20% на похудение, +15% на набор). Даёт «широкие» диапазоны макросов ради разнообразия блюд. Расчёт можно вручную переопределить.
- **Типы диет-пресеты:** Paleo, Keto, Vegetarian, Vegan, Mediterranean + «Anything». Пресет автоматически подстраивает рекомендации макросов и включает keyword-фильтры (например Paleo исключает злаки).

**Вывод для Рациона:** онбординг = «машина сбора данных, которая сразу выдаёт готовый план». Ключ — минимум шагов до первого сгенерированного дня/недели.

### 1.2 Генерация плана (день / неделя)

- **Однодневный планировщик (free):** один день под цели, неограниченные перегенерации вручную «пока не понравится».
- **Недельный планировщик (premium):** 7 дней сразу, скоординированно; оптимизация под (a) минимум отходов, (b) разнообразие, (c) точное попадание в макросы. Запускается **автоматически за день до дня закупки**. Можно вручную перегенерировать сразу несколько недель.
- **Meal Layout (раскладка приёмов):** пользователь задаёт, какие приёмы пищи есть в каждый день недели; на разные дни — разное время готовки и разные профили питания. Изменения раскладки **не** перегенерируют существующий план автоматически — нужен ручной запуск.

### 1.3 Уровни перегенерации (важнейший паттерн генератора)

Три уровня, все работают по логике **«autocomplete» — добор до дневной цели КБЖУ**:

1. **Весь день / вся неделя** — кнопка shuffle. Веб: наведение → кнопка; мобайл: свайп по приёму/дню. Модалка с диапазоном дат «Regenerate entire week».
2. **Один приём пищи** — новый приём считается так, чтобы добить недобор дня. Пример: план 1800 ккал, цель 2000 → перегенерация «200-калорийного» приёма даёт ~400 ккал. Учитывает настройки типа приёма, но игнорирует «meal size».
3. **Одно блюдо/продукт** — свап одной позиции внутри приёма; новое блюдо заполняет пробел, созданный удалением. Структура приёма сохраняется.

### 1.4 Замена блюда и альтернативы

- **Drag-and-drop:** веб — тянуть из сайдбара Food Bank в план; мобайл — «+» → выбрать блюдо → выбрать приём.
- **Список альтернатив:** «More → List alternative meals» показывает N альтернативных рецептов для того же слота. Есть фильтр «только из продуктов кладовки».
- **Ручные правки:** удалить блюдо, добавить своё — итоги КБЖУ пересчитываются.

### 1.5 Порции и цели приёмов

- **Family meal:** «Plan this meal for N people» — масштабирует ингредиенты в списке покупок (но НЕ масштабирует КБЖУ-цель).
- **Настройки типа приёма:** доступное время готовки, можно/нельзя готовить, сложность, размер приёма, включать ли «завтраковые» продукты, число едоков, «только recurring-продукты».
- **Meal size** используется только при генерации с нуля, НЕ при перегенерации одного приёма (чтобы дать ручную донастройку).

### 1.6 База рецептов/продуктов, поиск, фильтры

- Большая база рецептов с нутриентами; поиск по названию блюда или ингредиента.
- **Custom foods** (ввод этикетки вручную) и **custom recipes** (список ингредиентов → авторасчёт КБЖУ). Кастомные рецепты подхватываются генератором; кастомные продукты — только через recurring или как ингредиент.
- **Food Bank / Browse by nutrient:** сортировка по любому нутриенту (веб), вкладка **Pantry** — рецепты только из имеющихся продуктов.
- **Keyword-фильтры «I don't want to eat»:** исключение по словам в названии/ингредиентах; пресеты диет автозаполняют.

### 1.7 Предпочтения: избранное, блокировки, recurring, keyword-исключения

- **Favorites (сердечко):** небольшой бонус в алгоритме → чаще появляется.
- **Block (иконка блока):** навсегда исключает продукт из всех будущих планов (нельзя разблокировать точечно на один приём).
- **Recurring foods:** список с частотой «often» (значительно чаще) или «always» (всегда в плане). Чекбокс на типе приёма «Only use recurring foods in this meal» → генератор выбирает только из recurring. Кол-во recurring регулирует разнообразие (3-4 = повторы, 10+ = вариативность).
- **Keyword-исключения:** исключить целые категории (dairy, nuts, processed…).

### 1.8 Список покупок и агрегация

- Генерируется из недельного плана, показывает точные ингредиенты на неделю, обновляется при изменении плана.
- **Автосинхронизация** с планом; ручные правки (кол-во/удаление/добавление) ломают синк до кнопки «Reset Groceries».
- **Консолидация:** одинаковые ингредиенты суммируются в одну строку (2 lbs + 1 lb chicken = 3 lbs). Суммирование по всем едокам семьи.
- **Экспорт:** печать/email (есть «condensed» без картинок), **«Order with Instacart»** — экспорт в один клик в сервис доставки.

### 1.9 Кладовка (pantry)

- После закупки продукты переносятся из списка покупок в кладовку, кол-во подгоняется под реальные упаковки.
- Ингредиенты **автосписываются** на следующий день после потребления (или ручная кнопка «update pantry»).
- Недельный генератор **приоритезирует использование продуктов из кладовки** (заявлено 80-90% утилизации против ~70% среднего). Полностью «только из кладовки» не форсируется — обход через recurring + «only recurring».

### 1.10 Остатки (leftovers) и meal prep

- **Leftovers patterns:** какие приёмы порождают остатки, какие их потребляют, сколько дней хранятся. Автораскладка остатков в окне хранения + визуальный «leftovers preview».
- Обновление блюда-источника обновляет все связанные экземпляры.
- Примеры паттернов: «Ужин → следующие 2 обеда», «Meal Prep Sunday → вся неделя».
- Ручное «Create leftovers» на карточке рецепта. Остатки можно полностью выключить.

### 1.11 Трекинг съеденного и статистика

- **Логирование через редактирование плана:** удалить несъеденное, добавить реально съеденное — итоги КБЖУ обновляются, кладовка автосписывает. Отдельного «дневника» нет — план и есть трекер при отклонениях.
- **Next meal** (мобайл): ближайший неотмеченный приём.
- **Stats page (веб):** графики калорий, макросов, микронутриентов во времени vs цели.

### 1.12 Сохранённые планы и шаринг

- «Save to profile» / «Load from profile» — по сути copy-paste планов. Free: 1 план, Premium: до 20.
- **Шаринг:** сохранённый план получает публичный URL (`/shared/[id]`); ссылка работает как реферальная (обоим бонус при апгрейде).

### 1.13 UX-детали генератора (что делает продукт приятным)

- **Мгновенная генерация** (секунды) + неограниченные перегенерации → ощущение «игры с автоматом».
- **Три гранулярности перегенерации** (день/приём/блюдо) с autocomplete-добором — пользователь всегда попадает в цель без ручного счёта.
- **Изменения настроек не ломают текущий план** молча — защита от потери данных, ручное применение.
- Инлайн-подсказки, свайпы на мобайле, hover-кнопки на вебе, иконки (shuffle/heart/block).
- **Слабое место ETM (2026-обзоры):** блог/подход не обновлялись с ~2020; генератор иногда предлагает то, что «никогда не приготовишь» → возможность для дифференциации через «аппетитность» и реалистичность.

## 2. piknifood и российские сервисы — что перенять под РФ

### 2.1 Ключевая идея Pikni Food (из архитектурного разбора)

**Pikni Food = не генератор рецептов, а планировщик продуктовой корзины.** Главная проблема, которую он решает: меню требует 620 г гречки, а в магазине пачка 900 г; 180 г творога — а упаковка 400 г. Разница между «съеденными граммами» и реальной покупкой = лишние 200+ ₽ и остатки.

**Схема пересчёта:** профиль (цели/КБЖУ/бюджет/аллергены/техника) → допустимое меню → покупка целых упаковок → прогноз остатков → план готовки.

Алгоритмы (для справки, влияет на модель данных):
- **Готовые рационы (шаблоны)** — предсчитанные планы для частых сценариев; при запросе выбирается шаблон и дорабатывается, а не считается с нуля.
- **Simulated Annealing** в рантайме «трясёт» меню целиком; «энергия» учитывает отклонение КБЖУ (допускает колебания внутри дней), выход за бюджет, повторы блюд, скоропорт-остатки (штраф выше), использование продуктов из холодильника (бонус).
- **MIP (HiGHS)** — только офлайн для генерации шаблонов и проверки.
- **Hard-ограничения** (аллергены, стоп-лист, техника) vs **soft** (КБЖУ, бюджет, разнообразие, остатки). **Честно показывает компромисс**, а не пустой экран.

**Механика упаковок/остатков (важно для модели):**
- Ингредиент: `pack_size_g`, `price_per_pack`, `shelf_life_days`.
- Различают **реальные остатки** (в холодильнике), **pending-остатки** (прогноз после ещё не совершённой закупки — нельзя смешивать!), **snapshot утверждённой покупки** (фиксирует состав корзины, чтобы обновление цен не пересчитывало согласованный заказ).
- Список покупок как подсистема: суммирует по едокам → вычитает реальные остатки → округляет до пачек → пересчитывает стоимость → прогнозирует новые остатки; различает скоропорт (творог/свежее) и долгоживущее (крупы/масло).
- **Price snapshot:** локальный патч цен `ingredient_id → retailer_sku_id → price + pack_size + capture_time`; кэш 30 мин, stale-if-error до 12 ч; интерфейс честно пишет «ориентир по городу», а не «точная цена».

**Meal prep:** блюда группируются в **сессии готовки** с временем, порядком действий и параллелизмом (рис варится → рядом готовим курицу).

**Платформа:** React/PWA + Service Worker (offline) + Telegram Mini App (CloudStorage лимит 4096 байт/ключ). Фокус MVP — retention, не монетизация.

### 2.2 «Аппетитность» и подача карточек блюд

Из сравнения UX российских сервисов доставки продуктов:
- Крупное «вкусное» фото блюда как главный элемент карточки, минимум текста поверх.
- Быстро считываемые сигналы: КБЖУ/ккал, время готовки, цена/порция, теги (веган/острое/быстро).
- Готовые «наборы одним кликом» с обложкой рациона.

**Перенять:** качественная визуальная подача блюд (фото/иллюстрация), лаконичная карточка с 3-4 сигналами, «один клик = готовый рацион». Это прямой ответ на слабость ETM («сгенерировал то, что не приготовишь»).

### 2.3 Готовые рационы «в один клик»

- Библиотека предсобранных рационов под сценарии (похудение, набор, вегетарианский, бюджетный, «быстро без готовки», семейный).
- Пользователь выбирает готовый рацион → сразу видит меню недели + список покупок → дальше донастраивает свапами.
- Технически это шаблоны Pikni Food: быстрый старт без «пустого генератора».

### 2.4 Доставка продуктов по списку покупок в РФ (реалистичность интеграции)

Ландшафт (для планирования поздних волн):
- **Экспресс-доставка продуктов:** Яндекс Лавка, Самокат (Сбер), Купер (экс-СберМаркет), Ozon Fresh, ВкусВилл, Магнит/Пятёрочка (X5) доставка, Утконос.
- **Реальность API:** публичного «положи мой список в корзину» B2C-API у ритейлеров, как правило, **нет**. Яндекс Доставка предоставляет API логистики (создание заказов на доставку), но это не «корзина продуктов из списка». Основная сложность (как и у Pikni Food) — **матчинг SKU**: позиция каталога vs реальный товар в конкретном магазине/городе без официального API.

**Реалистичная стратегия интеграции (по волнам):**
1. **MVP:** список покупок «пачками» + экспорт (текст/PDF/шаринг ссылки), копирование в буфер. Никакой глубокой интеграции.
2. **Поздняя волна — «мягкая» интеграция:** deep-link/поиск по названию товара в приложении ритейлера (открыть Лавку/Самокат с предзаполненным поиском по позиции). Прайс-снапшот «ориентир по городу».
3. **Дальняя волна — партнёрская:** официальное партнёрство/API конкретного ритейлера или агрегатора для наполнения корзины; требует SKU-маппинга и договорённостей.

## 3. Что входит в MVP, что — в поздние волны

Целевой MVP-поток: **онбординг → генерация недели → база → список покупок пачками → кладовка → трекинг.**

### 3.1 MVP (must-have)

| Блок | Что берём из конкурентов |
|---|---|
| **Онбординг + КБЖУ** | Минимальный профиль (пол/возраст/рост/вес/активность/цель), калькулятор (Mifflin-St Jeor + активность + корректировка под цель), пресеты диет с keyword-фильтрами, диапазоны макросов ради разнообразия. Быстро до первого плана. |
| **Генерация недели** | Недельный план сразу; **готовые рационы-шаблоны** для быстрого старта (Pikni). Три уровня перегенерации (неделя/приём/блюдо) с autocomplete-добором до цели (ETM). Hard vs soft ограничения + честный показ компромисса. |
| **База рецептов/продуктов** | Поиск по названию/ингредиенту, keyword-исключения, базовые фильтры. Модель ингредиента с `pack_size`, `price_per_pack`, `shelf_life`. |
| **Список покупок «пачками»** | Агрегация/консолидация по всем едокам, округление до целых упаковок, прогноз остатков, разделение скоропорт/долгоживущее, ценовой «ориентир». Экспорт (текст/PDF/ссылка). |
| **Кладовка (pantry)** | Перенос из списка после закупки, авто/ручное списание, приоритет использования остатков в генераторе. Строгое разделение реальных vs pending-остатков + snapshot утверждённой покупки. |
| **Трекинг** | Логирование через правку плана (удалить/добавить съеденное), пересчёт КБЖУ, авто-списание кладовки. Базовые дневные итоги vs цель. |
| **Предпочтения (базовые)** | Favorites (бонус), Block (исключение), keyword-исключения. |
| **UX-приятности** | Мгновенная генерация + неограниченные перегенерации; настройки не ломают текущий план молча; «аппетитные» карточки блюд (фото + 3-4 сигнала). |

### 3.2 Поздние волны (nice-to-have)

- **Recurring foods** с частотами «often/always» + «only recurring in this meal».
- **Leftovers patterns** (какие приёмы порождают/потребляют остатки, окно хранения, meal-prep-паттерны «на всю неделю»).
- **Сессии готовки / meal prep** с временем, порядком и параллелизмом.
- **Разные профили питания по дням** (тренировочный/отдых) + гибкая раскладка приёмов (Meal Layout).
- **Family/порции на N человек** с масштабированием списка.
- **Статистика во времени** (графики калорий/макросов/микро vs цели).
- **Сохранённые планы + шаринг** (публичная ссылка, реферальность).
- **Кастомные рецепты/продукты** пользователя, подхват генератором.
- **Интеграция доставки РФ:** сначала deep-link/поиск в приложениях ритейлеров (Лавка/Самокат/Купер/Ozon Fresh/ВкусВилл) с прайс-снапшотом «ориентир», затем партнёрское наполнение корзины (требует SKU-маппинга).
- **Расширенные микронутриенты** (клетчатка/натрий/холестерин) и лимиты.
- **Telegram Mini App / PWA offline** как канал (по опыту Pikni Food).

## 4. Краткий свод дифференциации (что делать лучше конкурентов)

- **Аппетитность против ETM:** ETM генерирует технически верно, но «не всегда съедобно на вид». Ставка на визуал блюд + реалистичные рецепты — прямое конкурентное преимущество под РФ.
- **Планировщик корзины, а не рецептов** (ключевой инсайт Pikni Food): считать реальные пачки, остатки и деньги, а не только «граммы в тарелке» — это то, чего нет у ETM в явном виде и что болит у пользователя.
- **Честность о компромиссах:** показывать, где не сошлось (бюджет/КБЖУ), вместо пустого экрана.
