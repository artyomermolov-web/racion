# 17: Своё — кастом-продукт, кастом-рецепт, персонализация

**What to build:** Пользователь добавляет собственный продукт с ручным вводом КБЖУ, создаёт свой рецепт (генератор его использует) и персонализирует базовый рецепт так, что его версия заменяет оригинал в новых планах.

**Blocked by:** 13, 15

**Status:** resolved

Опирается на решения: 04, 06.

- [x] Кастом-продукт (ручной КБЖУ): доступен вручную и как recurring, генератор сам его не берёт.
- [x] Кастом-рецепт: генератор его использует наравне с базой.
- [x] Персонализация базового рецепта: своя версия (baseRecipeId) подменяет оригинал в новых планах.
- [x] Тест: персонализированный рецепт вытесняет базовый при генерации.

## Comments

Реализовано на существующих полях схемы (`Ingredient.isCustom/ownerUserId`, `Recipe.isCustom/ownerUserId/baseRecipeId` из decision 04) — миграция не потребовалась.

Ядро `/core/generator` (чистые швы, покрыты тестами):
- `custom.ts`: `resolvePersonalization` — своя версия (`baseRecipeId`) вытесняет базовый рецепт из пула кандидатов; `productCandidates` — кастом-продукт попадает в кандидаты ТОЛЬКО как recurring («генератор сам его не берёт»), с аллергенами/keywords, доступен во всех слотах.
- `custom-input.ts`: валидация ввода продукта (ручной КБЖУ) и рецепта/персонализации.
- Тесты `custom.test.ts` / `custom-input.test.ts`: персонализированный рецепт вытесняет базовый **и реально ставится** при генерации; продукт не берётся без recurring; валидация.

Проводка: `loadRecipePool` грузит базу + свои рецепты, применяет `resolvePersonalization`, и подмешивает recurring кастом-продукты (`poolForGeneration`) во все точки генерации (день/неделя/реген/замена). `lib/customFood.ts` — CRUD своего; recurring продукта живёт в общей `RecurringRecipe` по строковому id (общий помощник `applyRecurring`).

UI: экран `/svoe` (создание кастом-продукта с ручным КБЖУ + переключатель «В план», список своих рецептов); редактор рецепта `/svoe/recept/new` с живым расчётом КБЖУ из состава; «Персонализировать» с карточки базового рецепта (`?base=`) предзаполняет форму оригиналом, своя версия заменяет прежнюю персонализацию; свои продукты/рецепты видны в Базе с пометкой «Своё».

Осознанный шов: «доступен вручную» для кастом-продукта ограничен тем, что план в «тонком» слое не персистится и ручного добавления блюда в приём ещё нет (как отложенные остатки в тикете 15) — доступность = продукт создаётся, виден в базе и попадает в план как recurring; полноценное ручное добавление — в тикете трекинга/факта.

Все 180 тестов зелёные, `tsc --noEmit` чист. Сквозной путь (создание продукта, recurring-переключатель, персонализация с предзаполнением и заменой) проверен в браузере. Ручная приёмка — тикет 21.
