## Question

Какой полный набор пользовательских функций у Eat This Much (чтобы повторить функционально, ничего не копируя) и какие удачные решения есть у piknifood (визуал карточек блюд, готовые рационы, логика доставки продуктов в РФ)? Нужен структурированный разбор: экраны, ключевые фичи, UX-паттерны генерации/замены блюд/списка покупок; отдельно — что стоит перенять из piknifood под российский рынок. Только описание функциональности и паттернов, без копирования контента и дизайна.

## Answer

Полный разбор — в `.scratch/racion-mvp/research/competitors.md` (таблица MVP/поздние волны в разделе 3). Гист:

**Из Eat This Much перенять:**
- **3 уровня перегенерации** (неделя / приём / блюдо) + **autocomplete** — новый элемент добирает КБЖУ до дневной цели. Главный «приятный» паттерн генератора.
- Онбординг = сразу выдаёт план; тонкая система предпочтений (favorites-бонус, block-навсегда, recurring often/always + «только recurring», keyword-исключения).
- Кладовка с автосписанием и приоритетом; leftovers + meal-prep; список покупок с консолидацией.
- UX-правило: изменения настроек **не перегенерируют план молча**.
- Слабость (наш шанс): предлагает «неаппетитные»/неготовимые блюда → делаем ставку на аппетитность и реалистичность.

**Из piknifood перенять:**
- Это **планировщик продуктовой корзины**: считает реальные пачки, деньги, остатки (боль «нужно 620 г, пачка 900 г»).
- Модель ингредиента `pack_size` / `price_per_pack` / `shelf_life`; строгое разделение **реальные остатки / pending / snapshot покупки**.
- Честный показ компромисса вместо пустого экрана; готовые рационы-шаблоны; цена = «ориентир по городу».

**Доставка в РФ (реалистичность):** публичного B2C-API «наполни корзину по списку» почти нет (проблема матчинга SKU). Путь: MVP — список пачками + экспорт; позже — deep-link/поиск в Лавке/Самокате/Купере/Ozon Fresh/ВкусВилл; далее — партнёрское наполнение корзины. Подтверждает решение В6 (Лавка — отдельным вопросом после MVP).
