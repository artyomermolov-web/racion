# 08 — Аутентификация, аккаунты и приватность

Type: grilling
Status: resolved
HITL/AFK: HITL

## Question

Как устроены аккаунты и что заложить под приватность? Зафиксировать: email + пароль (bcrypt), модель сессий, привязку всех данных к пользователю, флоу регистрации/входа/выхода на русском; минимальный задел под будущие подписки (без реализации); базовый задел под 152-ФЗ при росте (какие перс. данные храним, согласие) — без избыточности для MVP. Вызвать `grilling`; при необходимости фактов по 152-ФЗ — точечный research.

## Answer

**Продуктовые решения (подтверждено):** вход — почта+пароль (соц-вход Яндекс/VK ID — задел); регистрация без подтверждения email, но со сбросом пароля по почте; приватность — по-минимуму (согласие + заглушка политики), полный 152-ФЗ при росте.

**Реализация MVP:**
- **Вход:** email + пароль, хеш **bcrypt**. Серверные сессии через httpOnly-cookie (лёгкая таблица `Session` или iron-session). Все данные строго привязаны к `User` (FK).
- **Регистрация:** мгновенный вход без подтверждения почты. Валидация email/пароля, понятные ошибки на русском.
- **Сброс пароля:** токен-флоу заложить сразу (`PasswordResetToken`); отправку письма в dev — ссылкой в лог/консоль, подключение реальной почты (SMTP/сервис) — при необходимости.
- **Соц-вход (задел):** модель `User` допускает внешние identity (Яндекс ID / VK ID) без реализации сейчас.
- **Приватность:** галочка **согласия на обработку данных** при регистрации + страница-заглушка «Политика конфиденциальности». Данные пол/возраст/вес трактуем осторожно (близки к данным о здоровье). Полный 152-ФЗ (хранение в РФ, явные согласия, договор оферты) — отдельной волной при выходе на широкий рынок.
- **Подписки:** модель `Subscription` — только задел, без пейвол-логики.
- **Экспорт данных в JSON** (право пользователя на свои данные) — есть в промпте, волна 2.

⚠ При росте до «уровня страны» вернуться к 152-ФЗ: локализация хранения ПДн в РФ, реестр согласий, политика удаления.
