# 18: Список покупок пачками

**What to build:** Пользователь видит список покупок за выбранный период (по умолчанию неделя от дня закупки) целыми магазинными пачками с суммой в ₽ и остатком по каждой позиции. Список живо синхронизируется с планом; вручную изменённые позиции замораживаются до сброса; есть галочки «куплено».

**Blocked by:** 15

**Status:** resolved

Опирается на решения: 07. Реализует ядро `/core/shopping` (без кладовки — она в 19).

- [x] Модуль `/core/shopping`: агрегация потребности × число едоков × порции → округление до целых пачек → сумма ₽ и остаток. (`src/core/shopping/{types,list,units}.ts`)
- [x] Тесты: округление и остаток (граничные), учёт едоков и порций. (`list.test.ts`, `units.test.ts` — 22 теста)
- [x] Экран списка с суммой ₽; живой синк с планом; заморозка ручных правок до сброса; чекбоксы «куплено». (`/pokupki`, `PokupkiContent.tsx`)
- [x] Печать / компактный вид.

**Задел / осознанные упрощения «тонкого» слоя:**
- Число едоков (`people`) — вход ядра есть, но `MealType.people` в схеме пока нет → в плане людей 1 (свой тикет).
- Вычет кладовки — шов `onHand` в ядре (по умолчанию пусто); наполнение — тикет 19.
- Штучные (яйца) переводятся г → шт через новое поле `Ingredient.gramsPerPiece`.
- «Живой синк»: список — проекция той же недели, что и на главной (общий стабильный seed); кнопка «Обновить из плана» — ре-синк, не случайная перегенерация. Ручной выбор диапазона дат («даты меняются вручную», реш. 07) отложен — в «тонком» слое у плана нет календарных дат/персистентности (появится вместе с датированным планом).
- Кастом-ПРОДУКТЫ как recurring-приёмы в список пока не раскладываются (у продукта нет разложимого на пачки состава) — задел с тикетом 17/19.
