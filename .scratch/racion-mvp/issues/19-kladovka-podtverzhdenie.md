# 19: Кладовка + подтверждение покупки

**What to build:** Пользователь подтверждает покупку — получает снапшот суммы, а купленное переносится в кладовку реальными лотами; список покупок вычитает то, что уже дома; следующая генерация приоритетно использует кладовку. Есть вкладка «что приготовить из того, что дома».

**Blocked by:** 18

**Status:** ready-for-human

Опирается на решения: 06, 07.

- [x] PantryLot: реальные и pending лоты строго раздельно; список вычитает только real.
- [x] Подтверждение покупки = снапшот (не пересчитывается при смене цен) + перенос купленного в real-лоты со сроком годности; pending → real.
- [x] Генератор даёт бонус за использование кладовки (приоритет).
- [x] Вкладка «приготовить из того, что дома».
- [x] Тесты: pending/real не смешиваются; снапшот не меняется при смене цен.

## Реализация

Ядро `/core/pantry` (чистое, покрыто Vitest): `realOnHand`/`pantryStockIds` (только
real), `confirmPurchase` (замороженный снапшот + real-лоты со сроком годности +
промоушен pending→real), `cookableFromPantry`. Бонус кладовки — в скоринге
генератора (`pantryBonus`, с потолком, чтобы не перебивать КБЖУ). Персистентность —
модель `PantryLot`; слой данных вычитает real-запас в списке покупок и кормит
генератор. UI — экран «Покупки» с сегментами «Список»/«Кладовка».

**Заделы (осознанно вне «тонкого» слоя):** писатель pending-лотов (нужен
персистентный список-прогноз) и персист снапшота между сессиями — как и сам
список, снапшот пока живёт на клиенте. Списание по факту «съел» — тикет 20.
