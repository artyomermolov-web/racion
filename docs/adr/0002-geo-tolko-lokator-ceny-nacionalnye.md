# ADR-0002 — Гео = только локатор магазинов; цены национальные

**Status:** Accepted (2026-09-12)

## Контекст

Требование предполагало «выбор магазина / города / региона», подразумевая, что от него зависят КБЖУ и стоимость товаров.

Разведка MCP ВкусВилл показала: гео-измерения у товарных инструментов **нет**. `products_search`, `product_details`, `product_analogs`, `products_discount` не принимают параметр региона/города/магазина и возвращают единую национальную цену. Гео присутствует **только** в инструменте `shops` — это справочник физических магазинов (регион/город/метро/фичи → адрес, координаты, часы); он не отдаёт ни цену, ни наличие по конкретному магазину.

## Решение

Выбор региона/города/метро реализуется как **локатор магазинов** в профиле пользователя (на базе `shops`) и служит только для показа ближайшего магазина и контекста корзины. На КБЖУ, цену и генерацию рациона он **не влияет**. Цены в системе — национальные.

## Альтернативы

- **Поштучная цена/наличие по магазину** — невозможно через данный MCP; потребовало бы иного источника данных. Вынесено за рамки; зафиксировано здесь, чтобы будущий читатель не искал несуществующий per-store pricing.
- **Полностью убрать гео** — отвергнуто: локатор магазинов полезен пользователю и задействует функцию `shops`.

## Последствия

- Ясная граница: «где купить» отделено от «сколько стоит».
- Если позже появится источник цен по магазину — это отдельное решение, не ломающее текущую модель (гео уже хранится в профиле).
