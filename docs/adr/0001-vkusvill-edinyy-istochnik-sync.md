# ADR-0001 — ВкусВилл как единый источник каталога/КБЖУ/цены через периодический синк

**Status:** Accepted (2026-09-12)

## Контекст

Каталог продуктов (211 ингредиентов) и цены в Racion были захардкожены в seed-данных, а цены явно помечены как ненадёжные («ориентир»). Появилось требование: КБЖУ, стоимость и ассортимент должны браться из ВкусВилл через их публичный MCP-сервер `https://mcp001.vkusvill.ru/mcp`.

Разведка MCP (проверено запросами) установила:
- Сервер открытый (без ключа), stateless JSON-RPC, 8 инструментов: `products_search`, `product_details`, `product_barcode`, `product_analogs`, `products_discount`, `shops`, `cart_link_create`, `recipes`.
- Жёсткий rate-limit: `product_details` отдаёт 429 уже на повторных вызовах; пагинация фиксирована 10/страницу.
- КБЖУ товаров — **неструктурированная русская строка** в `properties[].value`, часто с несколькими поставщиками через `<br>` (у молока — 5 вариантов, 66.8–84.8 ккал). У рецептов (`recipes`) КБЖУ структурные.
- `cart_link_create` только генерит `share_basket`-URL, не оформляет заказ.

## Решение

ВкусВилл — единый источник истины по каталогу, КБЖУ и цене. Данные **синхронизируются в локальную Prisma** периодическим прогоном (CLI `npm run vv:sync`, идемпотентный upsert), генератор и список покупок работают по локальному снапшоту. Live-вызовы MCP допускаются только для точечных действий (`cart_link_create`; опционально освежение цены), не для массовой генерации.

Следствия правил данных:
- КБЖУ-строка товара парсится в `FoodNutrients`, при нескольких поставщиках берётся **среднее**; сырьё сохраняется для аудита.
- Существующий seed **ре-сорсится по мэтчингу** с товарами ВВ; несопоставленное остаётся с фолбэк-значениями и помечается провенансом (`source`).
- Рецепты ВВ импортируются как рецепты Racion при сопоставлении **≥80%** ингредиентов; иначе пропускаются.
- Охват синка **курируемый** (нужные пищевые категории + товары, на которые ссылаются импортированные рецепты + ограниченный стартовый набор рецептов), а не весь каталог ВВ.

## Альтернативы

- **Live-вызовы на каждую генерацию** — отвергнуто: rate-limit (429) и пагинация 10/стр. делают сотни обращений на план нереальными; латентность и парсинг убивают UX.
- **Оставить собственный seed, ВВ — лишь обогащение (мэтчинг поверх)** — отвергнуто как источник вечного рассинхрона КБЖУ/цен и противоречащее требованию «всё из ВкусВилл».

## Последствия

- Плюс: настоящие КБЖУ/цены, покрытие ассортимента, задействованы все функции MCP.
- Минус: нужен тестируемый парсер грязных КБЖУ-строк и правило усреднения; расширение каталога через синк **сдвинет детерминированные недельные leak-тесты генератора** — чинить на уровне генератора/вердикта, не подбором данных под seed.
- Сеть изолирована в одном тонком адаптере; вся логика — чистые трансформации `core/vkusvill`, тестируемые на зафиксированных JSON-ответах.
